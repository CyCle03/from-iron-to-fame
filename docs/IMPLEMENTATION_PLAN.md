# 구현 로드맵

> 기준일: 2026-10-22. 2026-11-16 정적 코드 대조로 현재 상태를 교정했다. 이 문서의 상태 판정은 소스 근거이며, 테스트 실행·브라우저·모바일 실기기 검증은 별도다. 세부 규칙은 [GAME_DESIGN.md](GAME_DESIGN.md), [ESPORTS_RULES.md](ESPORTS_RULES.md), [RANK_AND_CAREER_SYSTEMS.md](RANK_AND_CAREER_SYSTEMS.md)를 따른다.

## 현재 기준선

이미 구현된 범위는 선수 생성, 12주 시즌 운영, 랭크·성장·장비, 3인 스쿼드와 KEL 4인 로스터, 지역 컵→마스터즈→KEL 커리어, 대회 픽 제한, 시즌 결산, 명예의 전당, 브라우저 자동 저장이다.

로드맵 1~4단계는 구현 완료다. 5단계는 기반 구현과 수치 조정·검증 보강이 남아 있고, 6단계 구조 개선은 진행 중이다. 이후 변경은 기능 수를 늘리기보다 **완주 가능한 커리어 흐름, 이전 저장 호환성, 장기 시뮬레이션 안정성**을 유지하는 것을 우선한다.

## 단계별 계획

### 1. 시즌 경쟁 구조 완성 — 구현됨

- 플레이어 1팀 + AI 47팀, 총 48개 스탠딩을 생성한다. 현재 모델링된 팀 필드는 전력(`rating`)·누적 CP(`points`)·승수(`wins`)·페이즈 순위(`phasePlaces`)·진출 자격(`qualification`)이다. AI 팀별 폼·로스터는 아직 모델에 없으며 확장 후보로 남긴다.
- 마스터즈 3개 페이즈의 전체 순위와 누적 CP를 보존한다.
- 상위 7팀 직행, LCQ 우승 1팀, 8팀 시즌 파이널을 실제 진출 흐름으로 연결한다.
- 시즌 종료 시 우승팀, 플레이어 최종 순위, 주요 기록을 커리어 이력에 남긴다.

완료 기준: 동일 시드에서 페이즈→LCQ→파이널 진출 결과가 재현되고, 48개 스탠딩·상위 7팀 직행·LCQ·8팀 파이널 테스트를 통과한다. 순위 동률은 승수→팀명 순으로 구현됐으나 동률 전용 테스트는 아직 없다.

구현 메모: 플레이어 포함 48개 스탠딩, 3개 페이즈 누적 CP, 승수·팀명 순 정렬, 상위 7팀 직행, LCQ 1팀과 8팀 파이널을 엔진·시즌 센터·커리어 이력에 연결했다.

### 2. 패치 메타와 실험체 풀 — 엔진·풀 구현됨, 결과 화면 보정 설명은 후속

- 시즌마다 메타 태그와 강세 역할을 생성하고 경기 전력 계산에 반영한다.
- 플레이어 숙련도와 팀원의 실험체·실력·폼·피로를 분리해 모델링한다. 팀원별 숙련도 수치는 아직 없다.
- 마스터즈 3-PICK-BAN과 KEL 2-PICK-CAP의 선택 이력을 대회 전체에서 확인할 수 있게 한다.
- 메타 적응, 숙련도, 조합 시너지의 영향도를 결과 화면에 설명한다. (계획) 현재 엔진은 `TournamentResult.modifiers`로 meta·mastery·roster 보정을 계산해 전력에 반영하지만, 대회 결과 카드에는 이 값을 렌더링하지 않는다. 실험체 풀 화면에서 메타 적합 +5와 숙련도만 확인할 수 있다.

완료 기준: 금지된 실험체를 선택하지 않고, KEL에서 동일 실험체가 세 번째 선택되지 않으며, 메타 보정의 근거가 UI에 표시된다. 앞의 두 조건은 테스트로 고정됐고, 결과 화면의 보정 설명은 아직 미충족이다.

구현 메모: 시즌별 강세 역할 메타, 선수별 3개 실험체 풀과 개별 숙련도, 밴·픽 제한에 따른 대체 픽, 메타·숙련도·로스터 보정값을 엔진에 반영했다. 실험체 풀 화면에서 메타 적합·숙련도를 확인하고 보조 실험체를 교체하거나 개별 숙련도를 훈련할 수 있다. 대회 결과 화면의 보정 근거 표시는 UI 후속 작업이다.

### 3. 팀 운영과 이적 시장 — 구현됨

- 스카우트 제안, 계약 기간·연봉, 재계약·이적 선택을 추가한다.
- 주전/후보 교체와 선수별 피로·폼·성장을 시즌 운영에 연결한다.
- 팀워크와 역할 시너지가 합동 훈련 및 로스터 변경에 따라 변하도록 한다.
- 계약 만료와 무소속 상태에서도 커리어가 막히지 않는 복귀 경로를 제공한다.

완료 기준: 입단→시즌 진행→재계약 또는 이적의 한 사이클을 완료할 수 있고, 저장 후 계약·로스터 상태가 유지된다.

구현 메모: 팀별 계약 기간·시즌 급여, 계약 만료와 자유계약 전환, 인지도·대회 경력 기반 스카우트 제안, 재계약과 이적 선택을 구현했다. 주전·후보 교체는 실제 대회 전력에 반영되며, 교체 직후 팀워크 손실과 합동 훈련에 따른 주전 폼 회복도 적용된다.

### 4. 기록·수상·은퇴 — 구현됨

- 대회 MVP, 시즌 베스트, 통산 우승·순위·대표 실험체 기록을 집계한다.
- 커리어 카드에 팀 이력, 트로피, 대표 실험체와 주요 기록을 포함한다.
- 은퇴 선택과 명예의 전당 심사를 분리하고, 헌액 실패 사유를 명확히 보여 준다.
- 은퇴한 커리어는 읽기 전용 기록으로 보존한다.

완료 기준: 신규 커리어부터 은퇴까지 진행한 뒤 기록 합계가 대회 이력과 일치하고, 커리어 카드 내보내기가 동작한다.

구현 메모: 대회 이력에서 통산 출전·우승·포디움·최고 순위를 집계하고, 마스터즈 시즌 베스트와 대회 MVP를 수상 기록으로 보존한다. 은퇴 후에는 읽기 전용 기록 보관소로 전환되며 별도의 명예의 전당 심사와 확장된 커리어 카드 내보내기를 제공한다.

### 5. 안정화와 밸런스 — 기반 구현, 수치 조정·검증 보강 진행 중

- 저장 데이터 마이그레이션과 손상 저장 복구를 버전별로 테스트한다.
- 고정 난수 시드 기반 장기 시뮬레이션으로 티어·인지도·우승 분포를 점검한다.
- 모바일 화면, 키보드 조작, 핵심 상태의 접근성 레이블을 검증한다.
- 공식 규칙을 바꿀 때 출처 문서와 팬게임 밸런스 값을 함께 갱신한다.

완료 기준: 단위·통합 테스트와 배포 빌드가 통과하고, 30시즌 자동 진행에서 중단·비정상 수치·저장 손상이 없다. (아직 미충족. 배포·서버 검증 절차는 [DEPLOYMENT.md](DEPLOYMENT.md)를 따른다.)

구현 메모:

- 저장 스키마 7, 공식 대회 이력 항목 구조 검증과 인지도 상한 교정을 포함한 마이그레이션을 적용했고, 파싱 불가능한 저장은 `parseGameSave`가 `null`을 반환하고 UI가 오류 토스트를 낸다. 숫자 범위를 벗어난 필드는 이 경로에서 거부되지 않는다.
- `validateGameState`는 능력치·재화·주차·실험체 풀·주전 인원의 불변식을 검사하지만 현재 테스트에서만 호출되며 가져오기 경로에는 연결되지 않았다.
- 고정 난수 30시즌 테스트는 `runSeason`만 반복한다. `advanceCareerSeason`, 공식 대회, 저장→마이그레이션→재개 왕복은 포함하지 않으므로 "30시즌 저장 무손상"은 아직 완료가 아니다.
- `advanceCareerSeason`은 `RandomSource` 주입과 시드 동등성 테스트를 갖췄지만, 앱 런타임 호출(`main.tsx`)은 기본 난수를 사용한다.
- 모바일 조작 크기는 44px 기준을 적용했으나 시즌 결산 닫기 버튼 38×38px 예외가 남아 있다(정적 CSS 근거, 브라우저 실측 아님). 읽기 전용 은퇴 화면은 구현됐다.

## 유지보수 작업 순서

### 2026-10-23 유지보수 감사 — 과거 스냅샷

이 절은 2026-10-23 작성 당시의 우선순위 목록이다. 원 계획은 이력으로 보존하고, 각 항목의 완료 표시는 2026-11-16 정적 코드 대조 결과다.

1. **P0 · 저장 이력 항목 구조 검증**: `competitionHistory` 배열뿐 아니라 각 항목의 시즌·종류·단계·순위·포인트를 검증한 뒤 인지도 상한 계산에 사용한다. `null`이나 잘못된 객체가 섞인 JSON도 예외 없이 복구되는 테스트를 완료 기준으로 삼는다. — 완료: `competitionRecords`가 항목을 검증·필터링하고 `recognitionCap` 계산에 사용한다.
2. **P1 · 시즌 유스케이스 난수 주입**: `advanceCareerSeason`에 `RandomSource`를 전달해 지역대회→마스터즈/KEL→시즌 결산 전체를 동일 시드로 재현한다. 현재 개별 시뮬레이터는 주입 가능하지만 이를 묶는 애플리케이션 유스케이스는 기본 난수를 사용한다. — API 주입과 시드 동등성 테스트는 완료됐으나, 앱 런타임 호출은 여전히 기본 난수를 사용한다.
3. **P1 · 명예의 전당 UI 회귀 테스트**: 플래티넘·인지도 100 저장을 불러와도 스타즈 버튼이 `선정 조건 미충족`이고 비활성인지 DOM 테스트로 고정한다. 엔진 조건 테스트는 있으나 카드 문구와 활성 상태를 직접 검증하는 테스트가 없다. — 완료: `HallOfFamePanel.test.tsx`가 버튼 문구와 비활성 상태를 검증한다.
4. **P1 · `game.ts` 추가 분할**: 1,366줄인 상태 전이 모듈에서 시즌, 계약·스카우트, 로스터, 대회 기록 갱신을 별도 도메인 모듈로 옮긴다. 공개 API 호환과 아키텍처 검사 통과를 완료 기준으로 둔다. — 완료: 2026-11-16 기준 `game.ts`는 1,118줄이며 시즌·계약·로스터·기록 갱신이 분리됐다.
5. **P2 · 장기 밸런스 관측**: 여러 고정 시드의 30시즌 배치 결과에서 티어, 공식 대회 진출률, 인지도, 스타즈·히어로즈·아너스 달성률을 요약해 극단값을 찾는다. — 측정 기반은 구현됐고 일부 시드 관측이 있으나, 수치 조정은 완료되지 않았다.

감사 항목 1~5의 측정 기반은 구현했다. 시즌 중간 대회를 반영한 대회 기준 RP 적용 후 30시즌 최적 플레이에서 마스터즈·KEL·히어로즈 100%, 아너스 65%가 관측됐다. 이 값은 당시 관측이며 전체 시드 분포의 완료된 검증이 아니다. 즉시 진행을 막는 오류는 없지만 상위 커리어 경로가 과도하게 흔한 상태이므로 시뮬레이션 기반 수치 조정은 완료되지 않았다. 상세 결과와 목표 범위는 `BALANCE_REPORT.md`에서 관리한다.

## 범위 원칙

- 실제 선수와 실제 경기 결과를 생성 데이터와 섞지 않는다.
- 공식 대회 구조와 팬게임용 수치·확률을 문서와 UI에서 구분한다.
- 기존 저장 키 `iron-to-fame-save-v1` 사용자의 진행을 가능한 한 보존한다.
- 새 기능은 엔진 테스트 없이 UI에만 구현하지 않는다.

## 6단계: 구조·운영 품질 개선 — 진행 중

- 커리어 생성 화면, 저장 수명주기, UI 공통 상수를 앱 진입점에서 분리한다.
- 시뮬레이션 난수 소스를 주입 가능하게 바꿔 동일 시드 재현성을 확보한다.
- 이후 게임 엔진을 시즌·랭크·계약·로스터 도메인으로 나누고 자동 품질 검사를 추가한다.

현재 구현: `game.ts`에서 시즌 주차·KeG/KEL 기록·마스터즈 시즌·로스터 교체·재계약을 별도 도메인 모듈로 분리했다. 생성 마법사, 시즌 센터, 대회 화면과 장비·기록·안내 화면을 독립 컴포넌트로, 자동 저장을 `useCareerGame` 훅으로 분리했다. 통산 집계·은퇴·명예의 전당은 `career`, RP 구간·티어·입장료는 `rank`, 지역 컵·팀 합류·마스터즈·KEL·팀 승격 자격은 `careerRules` 도메인으로 이동했다. 선수 생성·랭크·시즌·지역 컵·로스터·대회 시뮬레이터에는 공통 난수 소스 주입을 적용했다. JSON 저장 백업·복원, 초기화 확인, ESLint·Prettier와 GitHub Actions 자동 검증도 추가했다.
